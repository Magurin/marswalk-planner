## Что это

Perseverance уже нашел в Езеро места, куда стоит вернуться человеку: склад пробирок Three Forks, аргиллиты с органикой, «леопардовые пятна» Чейава-Фоллс. Marswalk Planner отвечает на практический вопрос: **можно ли от базы дойти туда пешком, поработать и вернуться живым** - с учетом уклонов, ресурса скафандра, кислорода, светового дня, связи и холода.

Приложение целиком работает в браузере. Сервер нужен только для двух необязательных вещей: ускорения карты (локальный кэш тайлов) и ИИ-помощника (прокси к OpenAI). Интерфейс на русском языке.

## Запуск

Нужен Node.js версии, которую поддерживает Vite 8 (20.19+ или 22.12+).

```bash
cd app
```

```bash
npm install
```

```bash
npm run dev
```

Приложение откроется на http://localhost:5174. Этого достаточно: рельеф, маршрут ровера и погода лежат в репозитории, тайлы карты идут напрямую с NASA Mars Trek.

### Необязательно: быстрая карта

NASA Trek отдает тайл за 1-4 секунды, только по HTTP/1.1 и без `Cache-Control`. Локальный кэш на Rust решает это:

```bash
cargo run --release --manifest-path tiles/Cargo.toml
```

Он слушает `127.0.0.1:8787`. При загрузке страница за 500 мс проверяет `/health` и, если кэш отвечает, берет тайлы у него - иначе идет напрямую в NASA. Ничего настраивать не нужно. Подробности в разделе [Кэш тайлов](#кэш-тайлов).

### Необязательно: ИИ-помощник

Создайте `app/.env.local`:

```
OPENAI_API_KEY=sk-...
```

и перезапустите `npm run dev`. Ключ не попадает в браузер: у переменной нет префикса `VITE_`, страница обращается к `/api/openai/...`, а заголовок с ключом добавляет dev-сервер. Без ключа прокси не создается, и помощник сообщает, что не подключен.

### Переменные окружения

| Переменная | Где | Зачем |
| --- | --- | --- |
| `OPENAI_API_KEY` | `app/.env.local`, настройки проекта Vercel | Ключ для помощника. Только на стороне сервера |
| `VITE_OPENAI_MODEL` | `app/.env.local` | Модель помощника, по умолчанию `gpt-5.4-mini` |
| `VITE_TILE_PROXY` | `app/.env.local` | Адрес кэша тайлов, по умолчанию `http://127.0.0.1:8787` |

### Проверки

```bash
npm run lint --prefix app
```

```bash
cargo test --manifest-path tiles/Cargo.toml
```

Линтер - oxlint. Тесты есть только у кэша тайлов (разбор пути тайла и сетка тайлов); у JS-части автотестов нет.

## Как пользоваться

- **База** (маркер `H`) - старт и финиш выхода. Перетащите маркер или выберите «Перенести базу». База и точки ставятся только внутри модели рельефа.
- **Точки** добавляются щелчком по карте или по научной цели. У каждой - время работы на месте. Маркеры можно перетаскивать, порядок менять.
- **Вердикт** пересчитывается после каждого изменения. Все допущения модели (скорость, масса, баллон и т. д.) редактируются в панели плана.
- **Ползунок Солнца** задает время для слоя теней; время старта выхода задается отдельно.
- **Горячие клавиши:** `Ctrl+K` - поиск и команды, `F` - полный экран, `H` - скрыть все панели, `P` - профиль высот, `Esc` - закрыть.
- На экранах уже 1024 px панели превращаются в выдвижные шторки с нижней панелью кнопок.

Что сохраняется и где:

| Что | Где |
| --- | --- |
| Текущий план (база, точки, допущения, способ прокладки) | `localStorage`, ключ `marswalk.plan.v3` |
| Сохраненные варианты | `localStorage`, ключ `marswalk.variants.v1` |
| Какие панели открыты | `localStorage`, ключ `marswalk.ui.v1` |
| Ссылка на план | `#plan=<base64url от компактного JSON>` в адресе. В ссылку попадают только допущения, отличные от значений по умолчанию |
| Экспорт | `marswalk-plan.geojson`: база, точки, линия маршрута с высотами, вердикт, проверки и допущения |

План из ссылки имеет приоритет над сохраненным в браузере. Аккаунтов и серверного хранилища нет.

## Как это считается

Вся модель лежит в `app/src/lib` и не зависит от интерфейса. Каждое число в ней - редактируемое допущение, а не полетное правило.

### Рельеф (`terrain.js`)

Основа - стереомодель MRO CTX: сетка 1596 x 1512 ячеек по 20 м (примерно 32 x 30 км вокруг Езеро), высоты от -2711 до -1516 м относительно MOLA.

- Файл `jezero_dem.u16` - это сырые `uint16` little-endian: `высота = значение * 0,05 - 3000`, то есть шаг 5 см; `0` означает «нет данных». Геопривязка лежит рядом в `jezero_dem.json`.
- Ячейка 20 м по широте, но по долготе на земле она короче в `cos(широты)` раз - это учтено в уклонах и расстояниях.
- Уклон считается оператором Хорна по окну 3 x 3. Шесть классов: 0-5°, 5-10°, 10-15°, 15-20° (предел скафандра), 20-30° (пешком нельзя), больше 30° (уступ).
- Расстояния - плоское приближение на сфере радиусом 3396,19 км; на масштабе выхода ошибка пренебрежима.

### Скорость и энергия (`eva.js`)

- **Скорость** - кривая в духе Тоблера от знакового уклона пути, отмасштабированная под ходьбу в скафандре: `v = v0 * exp(-3,5 * |уклон + 0,05| + 0,175)`. На ровном месте получается ровно `v0` (3 км/ч по умолчанию), быстрее всего - на пологом спуске 5%, минимум 0,08 м/с.
- **Метаболическая мощность** - Santee et al. (2001), форма для планетных выходов, которую использует планировщик SEXTANT (MIT), с марсианской гравитацией 3,71 м/с². Не меньше 120 Вт. На научной точке - фиксированные 220 Вт.
- **Кислород** - 20,1 кДж на литр O2, то есть 7,11e-8 кг на джоуль. Резерв рассчитан как 45 минут ходьбы при 300 Вт (около 0,06 кг) и должен остаться в баллоне к возвращению.
- Уклон пути знаковый, поэтому дорога туда и обратно стоит по-разному.

Значения по умолчанию:

| Допущение | Значение |
| --- | --- |
| Скорость по ровному | 3 км/ч |
| Масса астронавта со скафандром | 145 кг |
| Предельный уклон | 20° |
| Ресурс скафандра | 8 ч |
| Кислород в баллоне | 0,75 кг |
| Резерв кислорода | 45 мин |
| Мощность работы на точке | 220 Вт |
| Предел удаления от базы | 6 км по прямой |
| Запас до заката | 60 мин |
| Высота мачты связи | 10 м |
| Старт | 09:00 местного солнечного времени |

### Прокладка маршрута

A* по сетке 20 м с 8 направлениями, цена - время в пути.

- Ячейки круче предела закрыты. Исключение - сама цель: до точки на крутом склоне дойти можно, и это отразится в проверке уклона.
- Близость к пределу штрафуется: время на ячейке умножается на `1 + 1,5 * (уклон / предел)²`, поэтому маршрут предпочитает пологий обход ходьбе вдоль опасного края. Штраф влияет только на выбор пути; время и кислород считаются без него.
- Эвристика - расстояние по прямой, деленное на максимально возможную скорость, так что путь оптимален.
- Результат упрощается алгоритмом Дугласа-Пекера с допуском 6 м.
- Если прохода нет, участок рисуется прямой линией, а план получает вердикт «нельзя» с проверкой «Прокладка маршрута».
- Есть режим «по прямой» - для сравнения с наивной оценкой.

### Проверки готовности

Готовый маршрут проходится с шагом 20 м: в каждой точке известны высота, уклон, скорость, мощность, время, видимость базы и тень. Итоговый вердикт - худший из отдельных.

| Проверка | Нельзя | Осторожно |
| --- | --- | --- |
| Крутизна склонов | круче предела | ближе 5° к пределу |
| Ресурс скафандра | дольше лимита | больше 85% лимита |
| Световой день | старт до восхода или возврат после заката | возврат позже чем за 60 мин до заката |
| Удаление от базы | дальше предела | дальше 80% предела |
| Кислород | расход + резерв больше баллона | больше 90% баллона |
| Прямая видимость базы | мачта видна меньше чем с 60% пути | меньше чем с 90% |
| Тени на пути | - | больше 25% времени в тени |
| Температура воздуха | - | холоднее -75 °C |
| Покрытие моделью рельефа | - | часть пути вне модели |
| Аварийный возврат | не хватает кислорода или ресурса | остаток меньше половины резерва |

Нюансы:

- **Тень** считается для положения Солнца в тот момент, когда астронавт дойдет до этой точки, а не на время старта.
- **Радиотень** - прямая видимость от мачты на базе (10 м) до антенны скафандра (1,8 м) в радиусе 12 км, без дифракции и кривизны планеты. Пересчитывается при переносе базы и изменении высоты мачты.
- **Температура** - полукосинусный суточный ход между минимумом (чуть раньше восхода) и максимумом (13:30) по последнему солу MEDA с данными. Это только предупреждение: в расчет энергии холод не входит.
- **Восход и закат** - геометрический горизонт; вал кратера, закрывающий Солнце, учитывается не здесь, а в проверке теней.

### Зона достижимости, аварийный возврат, автоплан (`reach.js`)

Все три стоят на полях времени: алгоритм Дейкстры от базы до каждой ячейки в круге радиусом с предел удаления, с той же скоростью, пределом уклона и штрафом, что и у маршрута.

- Полей два: «от базы» и «к базе» - из-за знакового уклона они разные.
- Здесь 16 направлений (плюс ходы коня). С восемью зоны выходят восьмиугольными, а расстояния завышены до 8%.
- **Зона достижимости** - доля бюджета времени и кислорода, которую съест поход туда-обратно с 30 минутами работы на месте. Поля зависят только от базы, скорости, массы, предела уклона и предела удаления; баллон, ресурс и время старта меняют лишь раскраску, поэтому пересчета не требуют.
- **Аварийный возврат** - для каждой точки маршрута: что будет, если повернуть к базе прямо сейчас, идя вдвое медленнее и расходуя вдвое больше кислорода. Показывается худший момент выхода.
- **Автоплан** - точный перебор подмножеств (Хелд-Карп), не более 14 кандидатов в пределах удаления: сначала максимум целей, при равенстве - самый короткий выход. Поля чуть оптимистичнее точной модели по нарисованному маршруту, поэтому план считается с запасом 100%, 96%, ... 70% бюджета, и берется самый полный, который проходит жесткие проверки (время, свет, кислород, проходимость) уже на настоящем маршруте.

Тяжелые расчеты вынесены из главного потока: поля и автоплан - в `calc.worker.js`, тени - в `shade.worker.js` (около 0,3 с на кадр, карта не замирает при перетаскивании ползунка). Новый запрос того же типа отменяет результат предыдущего.

### Время на Марсе (`marstime.js`)

Алгоритм Allison & McEwen (2000), тот же, что в NASA GISS Mars24: Ls, уравнение времени, местное среднее и истинное солнечное время, склонение и направление на Солнце.

- Все времена в интерфейсе - **местное истинное солнечное время** Езеро (LTST).
- Номер сола откалиброван так, что посадка Perseverance (18 февраля 2021) приходится на сол 0.
- Поправка TAI-UTC зашита как 37 с (действует с 2017 года); при новой секунде координации ее нужно обновить.

### Научные цели (`catalog.js`)

Координаты целей не вбиты вручную: каждая цель привязана к номеру сола и ставится туда, где Perseverance был в этот сол по данным локализации. Последняя площадка Ingenuity берется из журнала полетов. Цели за пределами модели рельефа (гребень вала и дальше) видны на карте, но маршрут к ним проложить нельзя.

## ИИ-помощник

`app/src/lib/assistant.js`, OpenAI Responses API.

- Перед каждым обращением к модели собирается полный снимок плана в JSON: время, база, точки, результат со всеми проверками, допущения, цели, варианты.
- Модель меняет план только через 20 инструментов, каждый из которых вызывает то же действие хранилища, что и кнопка в интерфейсе. Поэтому любое изменение проходит обычный расчет, а цифры в ответе берутся из модели выхода, а не придумываются.
- За один вопрос - до 8 кругов вызовов инструментов; беседа продолжается через `previous_response_id`.
- Помощник выполнит и небезопасную просьбу (например, уменьшить резерв кислорода), но прямо предупредит.

## Кэш тайлов

`tiles/` - небольшой прокси на Rust (axum + reqwest), версия компилятора закреплена в `rust-toolchain.toml`.

- Каждый тайл хранится на диске бессрочно: тайлы неизменяемы.
- Ответы 404 тоже запоминаются, так что запросы за границу покрытия отвечаются мгновенно.
- Одновременные запросы одного тайла сливаются в одно обращение к NASA.
- Загрузка идет в отдельной задаче: Leaflet отменяет запросы при каждом сдвиге карты, и без этого брошенные загрузки навсегда занимали бы слоты.
- В фоне прогревается область Езеро - от мелкого масштаба к крупному и от центра наружу. У фона свой пул соединений, чтобы он не отнимал слоты у карты.
- Браузеру отдается `Cache-Control: immutable` и CORS-заголовки.

```
marswalk-tiles [--port 8787] [--cache DIR] [--no-prefetch] [--hirise-max 15] [--warm-conns 32]
```

Нюансы:

- Кэш по умолчанию пишется в `tiles/cache` и только растет. Если место ограничено, укажите `--cache` или отключите прогрев через `--no-prefetch`; `--hirise-max` задает, до какого масштаба прогревать HiRISE.
- Статистика - на `http://127.0.0.1:8787/health`.
- **Фото-текстура в 3D-виде доступна только с кэшем.** WebGL нужны тайлы с CORS-заголовками, а NASA Trek их не отдает. Без кэша остаются оболочки «Уклоны» и «Рельеф».
- Карта работает в проекции `EPSG:4326` (сетка тайлов Trek), а не в привычной Web Mercator.

## Данные

| Источник | Для чего |
| --- | --- |
| MRO **HiRISE** | Базовые снимки 25 см (NASA Mars Trek) |
| MRO **CTX** | Мозаика 6 м и стереомодель 20 м - основа уклонов, теней, радиотени и маршрутов |
| MGS **MOLA** | Цветная карта высот, опорные высоты |
| Mars Odyssey **THEMIS** | Дневной и ночной ИК: камень или рыхлая пыль |
| Орбитальные аппараты **Viking** | Глобальная цветная мозаика |
| Mars 2020 **Perseverance** | Маршрут, научные цели, погода MEDA, сырые снимки |
| Mars 2020 **Ingenuity** | Журнал полетов и площадки |
| MSL **Curiosity** REMS | Многолетний ряд сезонной погоды (кратер Гейл, не Езеро) |

**Снимки и живые данные.** Рельеф, маршрут ровера и погода лежат снимками в `app/public/data`, поэтому расчеты работают без сети. При запуске приложение дополнительно запрашивает свежие фиды mars.nasa.gov (погода MEDA и REMS, позиция ровера) и молча остается на снимках, если фид недоступен. Тайлы карты и сырые снимки камер всегда грузятся из сети.

### Обновление снимков

Скачайте [CTX DTM](https://planetarymaps.usgs.gov/mosaic/mars2020_trn/CTX/JEZ_ctx_B_soc_008_DTM_MOLAtopography_DeltaGeoid_20m_Eqc_latTs0_lon0.tif) в `data/raw/jezero_ctx_dtm_20m.tif` (папка в `.gitignore`) и выполните:

```bash
python -m venv .venv && .venv/Scripts/pip install rasterio numpy
```

```bash
.venv/Scripts/python tools/prepare_data.py
```

Можно обновить часть: `prepare_data.py dem`, `rover` или `weather` (последние два не требуют DTM).

> Скрипт пишет в `web/data` - папку первого прототипа. Приложение читает `app/public/data`, поэтому результат нужно скопировать туда вручную.

## Развертывание

Проект размещен на **Vercel** и связан с репозиторием: `main` уходит в продакшен, каждый PR получает свой адрес предпросмотра.

- `vercel.json` собирает `app/` и публикует `app/dist`. Сборка использует относительные пути (`base: './'`), так что работает из любого подкаталога.
- `api/openai/v1/responses.js` - серверная функция, двойник dev-прокси: добавляет ключ и пересылает запрос в OpenAI. Задайте `OPENAI_API_KEY` в настройках проекта; без него помощник отвечает, что не настроен.
- Эта функция не проверяет, кто к ней обращается, и не ограничивает частоту: любой посетитель сайта тратит ваш ключ. Для публичного демо задайте лимит расходов на стороне OpenAI.
- Кэш тайлов на Vercel не разворачивается - это локальный инструмент.

## Структура

```
app/                    Приложение на React
  src/lib/              Модель без интерфейса:
    terrain.js            рельеф, уклоны, тени, радиотень, A*
    eva.js                скорость, энергия, кислород, проверки
    reach.js              зона достижимости, аварийный возврат, автоплан
    marstime.js           марсианское время и положение Солнца
    assistant.js          ИИ-помощник и его инструменты
    catalog.js            научные цели, примеры планов, слои карты
    *.worker.js           расчеты вне главного потока
  src/store.js          Единое состояние (zustand): любое изменение плана
                        идет через commit и пересчитывает маршрут
  src/components/       Карта (Leaflet), 3D (three.js), панели, брифинг
  public/data/          Снимки рельефа, маршрута ровера и погоды
  public/models/        3D-модели Perseverance и Ingenuity
api/                    Функция Vercel: прокси OpenAI
tiles/                  Кэш тайлов NASA Trek на Rust
tools/                  Подготовка данных (Python)
web/                    Первый прототип на чистом HTML и JS, оставлен для истории
```

## Ограничения модели

- Сетка 20 м не видит камни, песчаную рябь и уступы меньше ячейки. Маршрут говорит, где склон проходим, а не куда ставить ногу.
- Свойства грунта не учитываются: рыхлый песок и твердая плита при одном уклоне стоят одинаково. Ночной ИК-слой THEMIS показывает разницу глазами, но в расчет не входит.
- Пыль и прозрачность атмосферы, радиация, тепловой баланс скафандра и расход воды в модели отсутствуют.
- Связь - чистая геометрия прямой видимости, без ретрансляторов и орбитальных аппаратов.
- Маршрут можно проложить только внутри модели рельефа CTX.
- Скорость, энергетика и лимиты - обоснованные допущения по опубликованным работам (Тоблер, Santee et al., опыт Apollo), а не сертифицированные характеристики конкретного скафандра.

> Marswalk Planner - помощь в планировании с открытыми допущениями, а не полетные правила.
